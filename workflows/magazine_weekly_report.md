# 매거진 주간 트렌드 리포트

## 목표
국내·해외 패션지, 남성지, 트렌드 매체의 **패션 기사만** 한 주 단위로 모아서 패션디자이너가 트렌드를 확인하는 **사진 중심 웹 리포트**를 만든다.
필수: 기사 요약 모음 / 컬러·소재 / 뜨는 키워드·아이템 / 여성복·남성복 구분 / 국내·해외 구분 / 시각 참고자료(사진).

## 비용 원칙 (사장님 결정, 2026-09-26)
유료 API를 쓰지 않는다. 기사 요약·분류는 **Claude가 직접** 한다 (Claude 요금제 안에서).
- **매주 금요일 오전 9시(KST) 자동**: Claude 예약 실행(루틴, 클라우드)이 아래 순서대로 판정 → 트렌드 문장 → 리포트 → push. 관리: https://claude.ai/code/routines
- 대화에서 "이번 주 매거진 리포트 만들어줘"라고 해도 같은 순서.

## 순서
Python: 사장님 PC는 `C:/Users/이채은/.local/bin/python3.14.exe` (Windows에서 `python`은 스토어 바로가기라 안 됨, 한글 출력은 `PYTHONIOENCODING=utf-8`). 클라우드(루틴)는 `python3`. 외부 패키지 없음(표준 라이브러리만).

| 단계 | 명령 | 결과 |
|---|---|---|
| 0. 최신 받기 | `git pull` | 자동 수집이 쌓아둔 기사 받기 (빼먹으면 푸시 때 충돌) |
| 1. 수집 | `python tools/fetch_articles.py` | 자동 수집 이후 새로 나온 기사 추가 (매체별 표 출력) |
| 2. 판정 묶음 뽑기 | `python tools/label_queue.py --next --date 리포트날짜 --size 60` | `.tmp/to_label.json` |
| 3. **Claude 판정** | 묶음을 읽고 `.tmp/batchN.json` 작성 → `python tools/label_queue.py --merge .tmp/batchN.json --date 리포트날짜` | `data/article_labels.json` |
| 4. 반복 | 2~3을 "남은 것 0개"까지. 마지막에 `--check` | 문제 없음 확인 |
| 5. 주간 트렌드 문장 | 집계를 보고 `data/weekly_notes.json`에 여성·남성 각 5개 트렌드 작성 (title, text, keys) | 리포트 요약 탭 무드보드 |
| 6. 리포트 | `python tools/build_report.py --date 리포트날짜` | `docs/index.html`, `docs/reports/날짜.html`, `docs/dates.json` |
| 7. 화면 점검 | Edge 헤드리스 캡처 (아래) | PC·휴대폰 확인 |
| 8. 올리기 | `git add data docs tools workflows` → 커밋 → `git push` | 고정 링크에 반영 (1~2분 뒤) |

리포트 날짜 = 7일이 끝나는 날 = 실행하는 금요일(한국 날짜). 7일 = 토~금. 첫 리포트만 예외로 2026-09-26(토, 9/20~26, 패션 기사 257개).
클라우드에는 `.tmp/snippets.json`이 없으므로 2단계에서 소개글을 기사 페이지에서 받음(60개에 약 2분). 받지 못하면(네트워크 막힘) 제목·분류만으로 판정하고 결과 보고에 적음.

## 판정 기준 (Claude)
- **패션(fashion: true)**: 컬렉션·런웨이, 트렌드, 아이템·쇼핑, 셀럽·스트리트 스타일, 패션 화보·디자이너 인터뷰, 디자인에 영향 있는 브랜드 뉴스(디렉터 교체, 협업, 생산지 논란).
- **빼기(false)**: 뷰티·헤어·그루밍, 시계만 다룬 기사, 하이주얼리 캠페인, 연예·영화 행사 소식, 실적·주가·소송·공급망·경영진 인사, 가구·자동차·음식·여행, 세일 모음.
- **성별**: 옷의 대상 기준. 여성 셀럽 룩 = 여성, 남성복 기사 = 남성, 스니커즈 발매·브랜드 전체 뉴스 = 공용. (리포트에서 여성 = 여성+공용, 남성 = 남성+공용)
- **이름표**: `tools/trend_keywords.json` 안에서만. 영어도 한국어 이름표로(burgundy → 레드/버건디). 없는 게 필요하면 이름표에 먼저 추가(추가 기록: 크링클/시어서커, 헤어리, 배색, 트랙 재킷).
- **요약**: 한국어 1~2문장, 디자이너가 알아야 할 것(무엇이·어떤 디테일/소재/컬러로·왜 뜨는지). 원문 문장을 옮기지 말고 새로 씀.

## 매체 (`tools/sources.json`, 15곳)
해외 패션지 ELLE·Harper's BAZAAR·W / 해외 남성지 Esquire·Men's Health / 국내 보그·W·GQ·엘르·바자·에스콰이어 코리아 / 트렌드 매체 Hypebeast·하입비스트 코리아·Highsnobiety·BoF.
- **넣지 않는 곳**: Vogue.com(Vogue Runway 포함)·GQ.com·GQ UK·Mr Porter·Guardian — robots.txt가 `Claude-User`를 막음. 요약을 Claude가 하므로 이 규칙을 지킴. `common.allowed()`가 자동 검사 → 새 매체도 막혀 있으면 수집 거부됨. 이름표를 바꿔 우회하지 말 것.
- 새 매체 추가 전: RSS 주소·robots.txt(`Claude-User` 포함) 확인 → 사장님께 보고.

## 사진 (시각 참고, 2026-09-26 사장님 요청)
- 피드의 사진 주소 사용. 없으면 기사 페이지의 공식 대표 사진(og:image). **본문 <img>는 쓰지 않음**(옆 칸 관련 기사 사진이 섞임 — W 코리아 캘빈클라인 기사에 엉뚱한 사진이 들어간 일).
- 사진 없는 기사 채우기: `python tools/fetch_articles.py --fill-images`
- 사진 파일은 저장하지 않고 매체 주소로 보여줌. 게시하는 글은 원문 제목 + Claude 요약 + 원문 링크만(저작권).
- **소개글(기사 앞부분)은 공개 저장소에 올리지 않음** (2026-09-26 사장님 결정): `.tmp/snippets.json`(로컬)에만. 자동 수집으로 모인 기사는 소개글이 없으므로 `label_queue.py --next`가 판정할 묶음만 기사 페이지 공식 소개(og:description)를 받아 채움(60개에 약 2분).
- 리포트는 같은 사진을 한 번만 보여줌: 하입비스트 영문·코리아판은 같은 사진을 다른(인코딩된) 주소로 씀 → 주소를 풀어 파일 이름으로 비교. 같은 사진 + 같은 첫 브랜드면 같은 기사로 합쳐 한 번만 셈("외 하입비스트 코리아" 표시).

## 리포트 구성
[여성 | 남성] × [전체 | 국내 | 해외] 전환. 주소 끝 `#남성/rw/해외`처럼 성별/탭/지역으로 특정 화면 공유(탭: sum 요약, kw 키워드, cm 컬러·소재, rw 런웨이, art 기사 모음).
1. 이번 주 요약 — 숫자 카드 + 트렌드 5개마다 사진 무드보드(키워드 겹침 많은 순, 트렌드끼리 사진 중복 없음)
2. 뜨는 키워드·아이템 — 아이템·스타일·디테일 순위, 줄마다 사진 8장 (지난주 기록이 있으면 ▲·새로 등장)
3. 컬러·소재 — 견본 색 + 사진 줄 (컬러 이름은 무신사 리포트와 같음)
4. 런웨이 — 브랜드별 사진 카드(리뷰 많은 순) + 런웨이 스타일·아이템 순위
5. 기사 모음 — 사진 카드, 기사 종류 필터

## 문제 대응
- **"요청을 거부함(403/429)"**: 그 매체만 멈추고 나머지는 계속. 재시도하지 말고 사장님께 보고.
- **패션 아닌 기사가 많이 섞임**: `sources.json`의 include/exclude 조정 → `python tools/fetch_articles.py --refilter` (판정 안 한 기사에만 적용). 분류는 단어 단위로 비교함 — 'Lifestyle' 안의 'Style'이 걸리던 문제(2026-09-26) 고침.
- **엘르·바자 코리아는 피드에 최근 3~8개만** 보여줌(엘르 3개 = 약 4시간치) → 3시간마다 자동 수집으로 대응. 그래도 빠지는 게 많으면 주기를 줄이기 전에 사장님께 확인.
- **판정 묶음 합치기 거부**: 출력된 이름표 밖 단어를 고치거나 이름표에 추가 후 다시 `--merge`.
